# 备份点三分与更新成功两段式判定

管理后台的「备份中心」与「系统更新」需要回答两个此前没有明确答案的问题：列出来的备份到底能不能恢复，以及一次更新到底算不算成功。本仓库现在并存三种数据副本介质（本机回滚快照、可离机的口令加密导出、宿主机定时冷备），更新作业又在主服务重启之前就把作业写成成功。如果不把介质语义与「成功」的判定固定下来，后续每加一处备份或每改一次更新流程，都会重复引入同一类误判。

## Decision

- **备份点 (Backup Point)** 是统一口径：某一时刻可恢复的数据副本，按介质与用途分为本机回滚快照、导出备份、冷备三种。管理后台把它们收拢成一份列表，每条标注介质、用途、来由（手动 / 覆盖导入前 / 更新作业前 / 回滚前）、体积、校验结论与可恢复性；宿主机冷备只读展示，以冷备任务写出的状态文件为主、目录扫描兜底。
- 备份是**不停写的**：SQLite 侧用官方 backup API 取得一致快照，照片文件靠校验和与完整性检查保证可用。冷备因此升级为「归档 + 清单 + 校验和」的单一交付物，而不是目录里的一堆 `.db` 文件；不为跨文件一致引入停写窗口。
- **校验分两层，语义严格区分**：备份点内一致性（该备份自己的库与自己的照片引用是否对得上）不一致 = 这份备份坏了，阻止恢复；跨备份点差异（当前数据库引用的内容不在这一备份点里）只是不匹配，提示、默认不勾选、允许管理员强制继续。两层都只做只读检查，不修改备份点。
- **卫生照片进备份**，按业务身份分两类并在归档内分开存放、可独立恢复：标准图（含全部历史版本）与其它照片（日常实拍、专项、整改回拍、教材）。缺标准图会让日常检查与待验收失去对照，缺其它照片只损失历史留痕，两者代价不同，不做成一个开关。`logs.db`、采集状态文件、`github_release.enc` 与更新作业状态明确排除在备份之外。
- **任何恢复前先给当前状态建快照**并标注来由；快照失败则拒绝执行该次恢复。保留份数可配置，本机回滚快照、导出备份的本机副本与冷备各有默认值与上限；超出上限时自动清理，但更新前快照与最近一份永不自动删，改配置时必须先展示「将删除哪些备份点」的预览（同一份计划既用于预览也用于实际清理，预览说什么就删什么）。
- **更新成功拆成两个事实**：更新作业只负责「已切换发行包并发出重启」，重启后的健康确认由管理后台按就绪口径完成（数据库已连接、迁移完成、关键表可读，且启动标识晚于本次重启）。健康确认失败落为 `succeeded_but_unhealthy`，保留回退点与日志直到下一次更新覆盖，页面持续显示并提供「回到上一版本」入口。
- **版本回滚不新开通道**：回到旧版本就是对该正式发行版再执行一次应用更新，仍走既有 Update Job 与预检。更新失败或未健康后不自动重试；页面提供手动重新检测与带冷却的自动重检。
- 更新历史落在业务库之外的旁路 JSON（默认保留 30 条），逐条记录目标版本、更新前版本、结果（成功 / 失败 / 取消 / 健康确认失败）、是否回滚、耗时与日志位置；上一次失败在预检里作为提示展示，不阻塞下一次更新。

## Considered Options

- **只保留一套备份机制**（仅加密导出，或仅本机快照）：拒绝。同机快照防误操作与更新事故，离机导出防整机故障，两者替代不了对方；把本机快照收进更新作业内部则会让「备份中心」无法回答日常恢复的问题。
- **冷备先停写再复制以取得跨文件一致**：拒绝。停写会打断正在下单的营业场景，而现有 SQLite backup API 加照片文件校验已足以给出可用结论，收益与代价不成比例。
- **标准图只备份当前版本**：拒绝。待验收日常冻结的是提交当时的标准图版本，只留当前版本会让恢复后的验收失去对照图；标准图数量少，全量历史几乎不增加体积。
- **把更新作业的结果当作最终成功**：拒绝。主服务重启后可能起不来或数据层不可用，作业先写成功会制造假阳性；在作业内等待健康又会把 Docker 自重启场景的进程生命周期变成判定依据。
- **健康确认失败时自动回滚或自动重试**：拒绝。新版本本身有问题的场景下自动动作只会重复受伤，且会抹掉「切过去了但没起来」这一关键证据；由管理员看到状态后决定回到上一版本。

## Consequences

- 备份包与冷备归档的格式都需要升级并带清单与校验和；旧备份点可以继续被列出与恢复，但会被标记出缺失内容（尤其是照片），不因此被拒绝。
- 冷备脚本的应用侧逻辑收敛到应用内备份服务，避免页面备份与冷备脚本继续各自实现一套。
- 更新作业的终态语义与 `job.json` 字段扩展；管理后台需要可写回作业状态与读取旁路历史的接口。
- `/api/system/health` 从固定返回健康升级为就绪口径，并需提供可比较的启动标识。
